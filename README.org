#+title: meow-ghostel - Meow integration for the Ghostel terminal
#+author: Daniel Kraus

[[https://github.com/meow-edit/meow][Meow]] modal editing for the [[https://github.com/dakra/ghostel][Ghostel]] terminal emulator: select with your
usual meow motions, then kill, change, replace, yank, or undo on the
shell's command line.

A Ghostel buffer is a read-only render of the terminal, and the text at
the prompt belongs to the shell, so meow's editing commands cannot modify
it directly.  =meow-ghostel-mode= sends each edit to the shell's own line
editor (readline, zle, fish, …) as cursor movement, backspaces, and
bracketed paste.  Motions and selections work over the whole buffer,
scrollback included, so output can be selected and copied like any other
text.

* Installation

Requires Emacs 28.1, meow 1.5.0, and Ghostel 0.61.0, or later.

From MELPA:

#+begin_src emacs-lisp
(use-package meow-ghostel
  :ensure t
  :after (ghostel meow)
  :hook (ghostel-mode . meow-ghostel-mode))
#+end_src

Or from source (Emacs 30+):

#+begin_src emacs-lisp
(use-package meow-ghostel
  :vc (:url "https://github.com/dakra/meow-ghostel" :rev :newest)
  :after (ghostel meow)
  :hook (ghostel-mode . meow-ghostel-mode))
#+end_src

* Usage

Meow ships no default keybindings; the keys below are those of meow's
suggested qwerty layout.  The mode remaps the =meow-*= commands, never
literal keys, so it follows whatever your =meow-setup= binds.

A Ghostel buffer starts in *insert state*, where every key goes to the
terminal.  =ESC= switches to normal state; =i= or =a= returns to typing.

For example, to fix the typo in =echo hello wrold= before running it:
=ESC= =b= selects =wrold=, =c= deletes it and enters insert state, then type
=world= and press =RET=.

| Keys                              | Command                                | In a Ghostel buffer                                       |
|-----------------------------------+----------------------------------------+-----------------------------------------------------------|
| =h= =j= =k= =l= =w= =b= =e= =x= … | motions                                | Move and select anywhere in the buffer                    |
| =y=                               | =meow-save=                            | Copy the selection                                        |
| =s=                               | =meow-kill=                            | Kill the selection; without one, kill to the end of input |
| =c=                               | =meow-change=                          | Delete the selection and enter insert state               |
| =r=                               | =meow-replace=                         | Replace the selection with the last kill                  |
| =d= / =D=                         | =meow-delete= / =meow-backward-delete= | Delete the character at / before point                    |
| =p=                               | =meow-yank=                            | Paste at point                                            |
| =u=                               | =meow-undo=                            | Undo in the shell (=Ctrl+_=)                              |
| =i= / =a=                         | =meow-insert= / =meow-append=          | Move the shell cursor to point and enter insert state     |
| =I= / =A=                         | =meow-open-above= / =meow-open-below=  | Enter insert state at the start / end of the input        |

Edits apply to the typed input only: a selection that reaches into the
prompt or the scrollback is clamped to it.  Killed text lands on the kill
ring as usual.

In full-screen programs (vim, less, htop) every command falls through to
vanilla meow and =ESC= goes to the program.

Bind =ghostel-previous-prompt= / =ghostel-next-prompt= in your =meow-setup= if
you want prompt navigation.

* Details

- *Motions* move point and select freely over the rendered rows; =j= stops
  at the live prompt row, and navigation in scrollback isn't yanked back
  by streaming output.  Outside insert state a selection stays active when
  the terminal repaints its rows (a prompt that redraws itself, output
  arriving on the selected lines); alt-screen programs still clear it.
- *Word boundaries* are Vim-style: =w=, =b=, =e= and =meow-mark-word= stop at
  path components (=bar= in =~/src/foo/bar.txt=), while the symbol commands
  (=W=, =B=, =E=, =meow-mark-symbol=) span the whole path; =e=/=b= selections
  take adjacent boundary characters along, as meow does for any symbol
  constituent, so =w= is the way to mark exactly one component.  Double-click and
  other syntax-based word commands see components too while the mode is on;
  set =meow-ghostel-word-boundaries= to =nil= to keep Ghostel's path-aware
  words.
- *Insert/append/open*: =A=/=I= go to the end/start of input because a
  terminal has no "open line".
- *Autosuggestions* (zsh-autosuggestions, fish, nu/reedline hints) are never
  accepted by accident: rightward motion and appends stop at the typed
  input end, detected by the suggestion's color.
- *Keypad*: =SPC= (keypad/leader) works as usual in normal state; in insert
  state it types into the terminal.
- *Insert-state Ctrl keys* reach the shell through Ghostel's own semi-char
  map (no extra passthrough layer), so =ghostel-keymap-exceptions= applies
  as-is: =C-u= stays =universal-argument= (remove it from the exceptions if
  you want readline kill-line).
- *Alt-screen programs* (vim, less, htop) are unaffected: every command
  falls through to vanilla =meow-*= there, and ESC routing follows
  =meow-ghostel-escape=.
- *Input modes*: outside semi-char input mode (Ghostel's =line= / =copy= /
  =emacs= / =char= modes) commands fall through to vanilla meow as well; in
  line mode the input is plain buffer text, so meow edits it directly.
- *Copy and Emacs mode* cooperate with the meow states.  Entering one from
  insert state switches to normal state, so motion keys browse the buffer
  instead of leaving the mode and typing into the terminal.  Entering
  insert state (=i=, =a=, =A=, =I=) leaves the mode and returns to the prompt;
  =i= and =a= keep point's column on the cursor row.  In normal and motion state,
  prompt jumps and search landings stay in semi-char: there
  =ghostel-prompt-navigation-input-mode= and =ghostel-point-leave-input-mode=
  are =nil= buffer-locally.

* Limitations

- *BEACON state*: its commands edit the buffer directly, but the terminal
  render owns that text, so the edits reach the shell at the terminal
  cursor rather than at each beacon.
- =meow-yank-pop= signals a =user-error=: a terminal echo cannot be swapped
  out.
- =meow-comment= signals a =user-error=: its =M-;= keyboard macro would type
  bytes into the shell.
- There is no redo.

* Customization

- =meow-ghostel-initial-state= (default =insert=) — initial meow state for
  new Ghostel buffers.
- =meow-ghostel-escape= (default =auto=) — where insert-state ESC goes:
  =auto= sends it to the terminal only in alt-screen mode (vim, less, …),
  =terminal= always, =meow= never.  Cycle per buffer with
  =meow-ghostel-toggle-send-escape=.
- =meow-ghostel-word-boundaries= (default: Vim's =iskeyword= complement,
  every printable ASCII punctuation except =_=) — characters that end words
  but join symbols.  =nil= keeps =ghostel-mode-syntax-table=; while a string
  is installed, =ghostel-word-boundary-string= only governs non-ASCII
  characters.

* Development

#+begin_src sh
make            # byte-compile + ERT tests + lint
make test       # ERT suite (test/meow-ghostel-test.el)
make lint       # package-lint + checkdoc + docquotes
make melpazoid  # full MELPA-style lint in a container
#+end_src

Dependencies are resolved from =MEOW_DIR= / =GHOSTEL_DIR= (defaulting to a
local =~/.emacs.d/lib/ghostel= checkout when present, else shallow cache
clones under =$XDG_CACHE_HOME=).  The native ERT tests need a ghostel
checkout with its Zig module built and self-skip otherwise.

Live end-to-end verification uses [[https://github.com/dakra/elate][elate]] scenarios under =test/elate/= that
drive a real ghostel + shell session over a PTY and let the shell itself
prove every edit landed — see [[file:test/elate/README.md][test/elate/README.md]].
